# Agent Note: 运维工作台与共享 SSH 服务

Status: implemented

## Problem

测试环境运维需要保存系统、服务和服务器之间的关系，复用脚本，并查看执行记录。SSH 插件已经拥有认证、主机配置和连接池。相邻的运维插件需要通过共享契约使用这些能力，让两个界面操作同一份仓库。

## Decision

`dsh-ops` 拥有系统/服务/服务器/任务定义、脚本与编排运行器、定时、通知和逐目标日志。Host 与浏览器半区通过包入口及 `./client` 挂载，聚合包在 `dsh-ssh` 之后加入它。

`dsh-ssh` 将 `sshTransport` 发布为 Cordis 服务。运维插件声明结构化契约并注入服务。该服务把主机增删改查、OpenSSH 配置导入、文件传输、连接检查和命令执行转交给已有仓库与引擎。OpenSSH 导入器与 SSH 页面使用同一实现。

脚本通过 stdin 传入，输出流写入运维运行仓库。该执行路径只尝试一次，避免连接中断后重放命令。已有缓冲式 SSH 执行保留连接重试行为。运维总开关同时控制调度器、路由和工具，Agent 公告默认关闭。

## Alternatives considered

在运维插件中直接导入 SSH 引擎会让构建图依赖另一个插件的内部实现，并产生第二个连接生命周期属主。共享服务让 SSH 持有唯一引擎。

每个流程步骤都由模型调用 SSH 工具，会让执行顺序和进度依赖 Agent 会话。运维运行器执行已保存的任务定义，并向 Agent 提供提交与查询工具。

## Consequences

凭据保存在 SSH 仓库中，摘要不携带凭据。运维路由使用家族共享的回环请求校验。远端浏览器部署提供经过认证的访问层。

运行记录在 Host 停机后保留，进程内运行器和锁随进程结束。重启后仍显示运行中的记录需要操作人员核对。编排引用脚本任务，支持有序步骤和相邻并行批次，多目标脚本运行按服务器串行执行。

共享服务导入回归测试使用隔离的 OpenSSH 配置。Host 入口测试验证关闭运维条目后不会创建定时运行。插件元数据与语言审计包含运维插件。
