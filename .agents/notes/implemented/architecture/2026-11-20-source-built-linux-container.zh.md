# Agent Note: 源码构建的 Linux 容器与认证回环入口

Status: implemented

## Problem

本地源码部署需要可复现的 Linux amd64 交付，包含运维工作台、在更新时保留应用状态，并让远程浏览器以相同的已认证所有者权限访问 SSH 和运维路由。仅打包宿主的 Docker 配方没有建立这些插件访问边界，也没有打包本地新增的工作区能力。

## Decision

根 Dockerfile 在 BuildKit 本机平台上使用 Node 24.22.3 和官方 DSH 0.2.2-rc.3 SDK 编译当前工作区。编译前删除已有包产物。经检查的构建交接仅包含 `packages/*/lib`：Node 与浏览器 JavaScript、声明与映射文件、图表供应商资源以及聚合 shell 标记。交接拒绝依赖目录、软链接和原生可执行文件，并排除增量缓存。源码所属的语言包、预设、工具、资源、shell 元数据和包清单来自干净的源码上下文。

目标平台宿主阶段独立保留官方 DSH 安装。目标打包阶段禁用生命周期脚本安装生产工作区依赖，将包产物替换为经检查的构建输出，随后用 pnpm deploy 创建独立生产依赖闭包。准备步骤修复聚合包自引用，验证 dsh-ops 存在，并将宿主提供的每项 SDK 依赖指向该目标宿主的同一套安装目录。SDK 遍历覆盖 pnpm 提升依赖所在的 `.pnpm/node_modules` 作用域以及各包本地依赖作用域，宿主未提供的 SDK 包保留已安装版本。构建平台 SDK 和依赖树不会进入运行镜像。构建上下文排除凭据和本地依赖目录。

工作区安装使用按架构分开的加锁 BuildKit pnpm 仓库缓存。构建诊断记录选中的 Node、libuv 和 pnpm 版本，仅记录 Node IPC 环境变量是否存在。规范安装过程将输出写入普通临时日志文件，进程结束后再打印日志。原始失败状态仍会终止编译和打包。镜像修订标签放在运行环境安装层之后，元数据变化不会重新执行操作系统包安装。

应用状态保存在 `/data`，工作文件保存在 `/workspace`。启动时创建 Web profile 并挂载已打包插件家族。已有的真实包目录保持有效，包软链接以原子方式更新到当前镜像的生产路径。新 profile 启用 SSH，后续 profile 设置持续保留。

DSH 宿主监听容器回环。公开代理检查配置的公开 Host 和 Origin，通过请求原生首页验证官方签名的浏览器所有者 cookie，随后才把请求转换为回环来源地址。携带启动 token 的导航交给原生首页建立该 cookie。HTTP 和 WebSocket 请求使用同一所有者验证。API peer 凭据无法通过该代理获得管理权限。

安装器将私有交付包的 registry.credentials 作为字面数据读取，并通过标准输入提交密码。更新过程串行执行，保留两个绑定挂载目录，替换实例启动失败时重新启动上一个受管容器。就绪判定要求原生入口、空的降级账本、运维树和 SSH 主机仓库均正常。

替换受管容器时，安装器沿用已有 `/data` 和 `/workspace` 绑定来源，显式配置的目录除外。同时保留容器配置的运行用户。因此，调用者主目录或 sudo 环境变化不会选中空的默认目录，也不会改变应用 UID 和 GID。

## Alternatives considered

曾考虑复制开发机的 node_modules，因原生模块与绝对工作区链接必须匹配 Linux amd64 及运行环境安装目录而放弃。独立生产依赖闭包使这些路径可以在构建时检查。

曾实际尝试通过 amd64 模拟编译全部工作区，因并行 TypeScript 编译每批消耗数分钟而放弃将其作为常规跨平台构建方式。本机编译保留 JavaScript 构建契约，独立目标安装则保证皮肤中心的 LightningCSS 和官方宿主原生依赖等运行模块匹配目标架构。

曾考虑直接公开 DSH 监听器，因 SSH 和运维路由会将远程套接字判定为回环范围之外而放弃。移除围栏会改变插件安全行为。容器入口先验证浏览器所有者，随后才转换已验证的请求。

早期[容器资产提案](../../rejected/architecture/2026-09-13-remote-web-ui-docker-assets.md)在项目缺少可验证 Docker 执行环境、范围仍是远程网页插件时被拒绝。这次交付将官方宿主与源码构建的应用插件共同打包，并通过容器构建与访问检查验证，边界归[部署指南](../../../../deploy/docker/README.md)说明。

## Consequences

交付物面向 Linux amd64，固定宿主版本。模型接入和 SSH 秘密在部署后配置，并持久化在镜像外。更新保留应用状态，镜像负责已打包插件代码。部署使用一个配置的浏览器来源地址，地址或代理变化时需要同步该值。

共享[回环分类](../bug-fix/2026-10-19-reverse-proxy-loopback-fence.md)保持有效。代理负责公开入口的认证与同源判断，只有已认证所有者的流量才会以本机请求形式送入私有监听器。原生容器健康检查也会识别网页外壳可达、管理插件却挂载失败的状态。

最初在 QEMU 7 下执行的 amd64 安装使用继承标准输入输出或普通文件日志均在 libuv 中以 SIGABRT 退出。构建环境升级到 QEMU 10 后，规范依赖安装和 SDK 恢复均成功完成。普通文件日志仍用于诊断，不被描述为崩溃修复。本机编译避免模拟执行开销较大的 TypeScript 构建，目标平台安装和容器访问检查仍负责验证最终镜像。Node 和 pnpm 版本继续固定，失败的安装不会被当作成功处理。
